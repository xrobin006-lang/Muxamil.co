# Setup Guide — Muxamil.co (CommHub)

Complete first-run setup. Time estimate: 15–20 minutes.

> Short version: `bash scripts/setup.sh` → fill `.env` → `bash scripts/dev.sh start`.

---

## 1. Prerequisites

| Requirement | Version | Check |
|---|---|---|
| Bun (recommended) | 1.1+ | `bun --version` — install: <https://bun.sh> |
| …or Node.js + npm | 20+ | `node --version` |
| curl, openssl, zip | any | `curl --version` etc. |
| Supabase account | free tier fine | <https://database.new> |

## 2. Unpack & install

```bash
unzip my-website-v1.0.0-*.zip -d muxamil
cd muxamil
bash scripts/setup.sh
```

`setup.sh` is **idempotent** and **never overwrites an existing `.env`**. It will:

1. Detect Bun or Node 20+
2. Create `.env` from `.env.example` and generate random `SESSION_SECRET` + `INTERNAL_API_KEY`
3. Create `mini-services/realtime-service/.env` mirroring the root values
4. Install dependencies (root + realtime sidecar)
5. Print the remaining manual steps (below)

## 3. Create the Supabase project (the database)

ALL production data lives in Supabase (Postgres + Auth + Storage) — there is no
local database in production. `db/custom.db` is legacy dev tooling only.

1. Create a project at <https://database.new>
2. Open **SQL Editor**, paste the full contents of
   `supabase/migrations/2026-08-30-init-schema.sql`, **Run**.
   It is idempotent (safe to re-run) and creates: 19 `mux_*` tables, indexes,
   RLS policies, triggers, 5 storage buckets, and the settings seed row.
3. Optional later features: `supabase/migrations/2026-08-30-pending-features.sql`
   (documents poll tables, notification preferences, profile banners).

## 4. Fill in `.env`

Open `.env` and set the real values:

| Key | Where to get it |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Settings → API → publishable (anon) key |
| `SUPABASE_SECRET_KEY` | Settings → API → secret (service-role) key — **server-side only** |
| `SESSION_SECRET` | already generated by setup.sh (`openssl rand -hex 32`) |
| `INTERNAL_API_KEY` | already generated by setup.sh |
| `REALTIME_SERVICE_URL` | `http://localhost:3004` (default, keep) |
| `NEXT_PUBLIC_SITE_URL` | your public origin, e.g. `https://muxamil.co` |
| `ADMIN_BOOTSTRAP_EMAIL` / `_PASSWORD` | the first admin account (see §5) |
| `AI_API_KEY` | optional — Google Gemini key (<https://aistudio.google.com/apikey>) |
| `AI_MODEL` | optional — default `gemini-3.6-flash` |
| `DATABASE_URL` | leave as-is (legacy dev tooling) |

Then re-run `bash scripts/setup.sh` so the sidecar `.env` picks up the Supabase
values (or copy them by hand — the 4 keys are documented in the file).

> **Build-time inlining:** `NEXT_PUBLIC_*` values are baked into the client
> bundle **at build time**. If you change them later, you must **rebuild**.

## 5. Bootstrap the first admin

Registration always creates a regular **member** — admin rights are never
granted through the UI.

1. Supabase Dashboard → **Authentication → Users → Add user**
   (email + strong password, auto-confirm).
2. **SQL Editor**:
   ```sql
   update mux_profiles
   set role = 'admin', is_verified = true, verified_at = now()
   where email = 'your-admin@example.com';
   ```
3. Put the same credentials in `.env` (`ADMIN_BOOTSTRAP_EMAIL` /
   `ADMIN_BOOTSTRAP_PASSWORD`) — this is the privileged-field bridge the
   backend uses for verify/block admin actions.

Log in at `/` — admins land on the dashboard automatically.

## 6. Run

**Development** (hot reload):

```bash
bash scripts/dev.sh start     # app :3000 + sidecar :3003/:3004
bash scripts/dev.sh status
bash scripts/dev.sh logs app
bash scripts/dev.sh stop
```

**Production** (self-hosted):

```bash
bash scripts/build.sh         # next build → .next/standalone
bash scripts/deploy.sh start  # sidecar + standalone server :3000
bash scripts/healthcheck.sh
```

## 7. Verify everything works

1. Open `http://localhost:3000` — the landing page renders.
2. **Sign up** a test account — you are signed in to the member app.
3. Footer (desktop) shows **“Realtime connected”** (sidecar healthy).
4. Admin login → dashboard KPIs render.
5. `bash scripts/healthcheck.sh` → `RESULT: HEALTHY`.

## 8. Troubleshooting

See [TROUBLESHOOTING.md](TROUBLESHOOTING.md). Most common issue: missing env
values → every API route fails with `[config] Missing environment variable …`
(fix: complete `.env`, restart).
